# Contributing

Thank you for your interest in contributing to Bug-Bounty-Payloads.

## What You Can Contribute

- New security testing payload collections.
- Improvements to existing payloads.
- Technical explanations and documentation.
- Reproducible testing examples.
- Automation scripts for authorized testing.
- Corrections to inaccurate information.

## Contribution Guidelines

1. Explain the purpose of your contribution.
2. Include technical context where relevant.
3. Avoid duplicate or unnecessary payloads.
4. Verify the accuracy of new material.
5. Document limitations and expected behavior.
6. Use clear and simple language.
7. Follow responsible security research practices.

## Security Requirements

- Do not submit credentials, API keys, or private tokens.
- Do not disclose private bug bounty findings.
- Do not include confidential information.
- Respect security program scope and policies.

## Pull Requests

Before submitting a pull request:

1. Review the existing repository structure.
2. Check for duplicate content.
3. Explain what you changed.
4. Describe its educational or practical value.
5. Verify the documentation.

All contributions are subject to review.

Thank you for helping improve this project.
